The Problem

1,962 upcoming events on Sun Devil Central iCal feed

No personal search. No easy way to find what matters.

Students drown in information overload.

2/8

The Solution

"Sol turns any firehose of unstructured ASU information into something a student can search, understand, and act on — powered entirely by ASU's AI Research Platform."

3/8

Demo 1: Events

Snap a flyer photo → Vision reads it

Hybrid BM25+embedding search matches the live event → Shows card

User: "reserve me a spot for the first one"

Tool loop: reserve_spot fails on guessed id → Model reads tool's JSON-Schema error → Calls search_events to recover real id → reserve_spot succeeds

3 tool calls, 1 turn, live.

4/8

Demo 2: HeatRoute

User asks: "MU to Hayden at 12:30 without frying"

Model calls plan_heat_route tool (22ms)

Shade-aware walking route, honest time estimate

5.6s end to end.

The AI reaches for the tool mid-conversation, no page navigation needed.

5/8

Demo 3: Notebooks

Upload page photos in order

qwen3-vl-32b-instruct OCRs each page

Running digest kept: Topics / Key facts / Connections / Open questions, each cites a page number

Example digest:

Topics: "Regular languages, finite automata (p.1)"
Key facts: "Pumping lemma disproves 0^n1^n is regular (p.2)"
Connections: "0^n1^n returns as a context-free grammar (p.3)"

Chat answers from digest + raw pages, cited.

Best line to demo live: "what is still unclear or unfinished?"

6/8

Built Entirely on AIR

Models & measured latency:

qwen35-27b (chat/reasoning, 1.7s, beat a 120B model on speed AND quality)
qwen3-vl-32b-instruct (vision/OCR, 5-12s)
qwen3-embedding-4b (retrieval embeddings, 278ms)
qwen3-coder-30b (wrote most of the app itself via opencode)

Usage: 486 gateway requests, 4.5M tokens processed during build week

Zero calls to anything but AIR.
