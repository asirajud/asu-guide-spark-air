## Harness notes (for reproducing)

- opencode 1.18.27, provider `asu` -> `https://openai.rc.asu.edu/v1`, ASU Cisco VPN required.
- **Backgrounded `opencode run` must be given `< /dev/null`.** Held up: with stdin closed, zero bootstrap hangs across 25 runs in this session (the previous build saw roughly half of them hang).
- **`opencode run` frequently writes the file in 20-50s and then hangs on the closing assistant turn.** Held up, but it bit far less often here than in the previous build — most runs exited cleanly on their own and only 2 of 25 had to be killed by the watchdog. Watchdog logic: poll the `--print-logs` stream, and once every expected file has changed _and_ the log has been idle for 25-30s, SIGKILL the process group.
- **New gotcha:** opencode resolves its session/instance directory from the shell's cwd when the target directory is not a git repo, ignoring the spawned process's `cwd`. A run launched from elsewhere writes its files into the _launcher's_ directory. Always `chdir` into the project before spawning.
- Prompt density is what makes this work. Every prompt named the exact file path, the exact exported signatures, and the exact classNames or literal strings. The models execute a spec faithfully and originate no design; the two things they invented unprompted (a `@/types/...` import, a `FormDataEntryValue` coercion) were both defects.
